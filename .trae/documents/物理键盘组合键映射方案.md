# 物理键盘组合键映射 —— 实现方案

## Context

当前程序的映射源只有手柄按钮：`XInputGamepadSource` → `SteamInput` → `MapperState::handle_button`，而 `MapperState` 的所有状态表都以 `ControllerButton` 为 key。角色状态（潜行/聊天窗等）已通过 SLState 像素读取进入 `app.states`，`KeyMapping` 也已具备 `state_conditions` / `state_logic`。

本次要新增一条独立的输入源：**物理键盘组合键**。用户在一个新设置页里添加多组「修饰键 + 主键 → 动作」规则，每组可带状态条件（或/与）。命中规则时吞掉原键并执行映射（按住保持、松开释放）；未命中或状态条件不满足时原键照常传给游戏。

## 数据流

```
WH_KEYBOARD_LL 钩子线程 ──命中且状态满足──> mpsc ──> kb-worker 线程 ──lock core──> AppCore::handle_keyboard_event
        │                                                                          └→ MapperState::handle_button(TriggerId::Kb(id), ...)
        └─ 未命中 / 自身注入 / 本程序前台 / 条件不满足 ──> CallNextHookEx（放行）
```

## 1. 数据模型

- `src/core/input_types.rs`：新增
  ```rust
  #[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
  pub enum TriggerId { Pad(ControllerButton), Kb(u32) }
  ```
- `src/core/mapping_types.rs`：
  ```rust
  pub struct KeyboardRule {
      pub id: u32,          // 稳定的规则 id（删除不复用，取 max+1）
      pub enabled: bool,
      pub ctrl: bool, pub shift: bool, pub alt: bool, pub win: bool,
      pub key_code: i32,    // 主键，Android KeyCode（与配置/核心层保持同一体系）
      pub mapping: KeyMapping, // 复用动作 / 子命令 / 状态条件
  }
  ```
- `ControllerProfile` 增 `keyboard_rules: Vec<KeyboardRule>`；
  `GlobalSettings` 增 `keyboard_rules_enabled: bool`（默认 true）。
- 键盘规则不使用长按（触发路径没有 Tick 驱动），触发时清空 `mapping.long_press/long_press_subs`。

## 2. 映射器改造（最小侵入的通用化）

- `src/core/mapper.rs`：8 张状态表（`pressed_main_keys`、`pressed_sub_keys`、`pressed_mouse_buttons`、`pressed_mouse_layer`、`toggled_mouse_buttons`、`toggled_mouse_layer`、`pending_long_press`、`long_press_buttons`）的 key 由 `ControllerButton` 改为 `TriggerId`；`handle_button`、`release_button_injection`、`check_long_press`（迭代处）、`handle_mouse_toggle`、`handle_state_macro` 等参数同步改类型。
- `src/core/mod.rs`：`UiEvent::MouseToggleChanged.button` 改为 `TriggerId`（Rust 侧无消费方，改动安全）。
- `src/core/app.rs`：手柄路径传 `TriggerId::Pad(button)`；新增
  ```rust
  pub fn handle_keyboard_event(&mut self, rule_id: u32, is_pressed: bool)
  ```
  逻辑：读全局开关 → 按 id 找规则 → `long_press` 清空 → 按下时用 `mapping.state_allows(|id| self.states.get(id))` 门禁、松开一律放行 → `mapper.handle_button(TriggerId::Kb(rule_id), is_pressed, &m, "", injector, event_tx, look)`（键盘规则无层概念，`layer_id` 传空串，且不经过 `SteamInput`，避免切层/切映射类动作）。

## 3. 键盘监听（新文件 `src/core/keyboard_source.rs`）

- **钩子线程**：`SetWindowsHookExW(WH_KEYBOARD_LL, Some(proc), GetModuleHandleW(None)?, 0)` + `GetMessageW` 消息循环；`stop()` 用 `PostThreadMessageW(tid, WM_QUIT, 0, 0)` 退出循环，在钩子线程内 `UnhookWindowsHookEx` 后 join（沿用 `xinput_source.rs` 的 `AtomicBool + JoinHandle` 范式）。
- **回调判定**（windows crate 0.62 现有 feature 已够用，无需新增）：
  1. `code < 0` → `CallNextHookEx`；
  2. `KBDLLHOOKSTRUCT.flags & LLKHF_INJECTED` → 放行（防止自身 SendInput 递归）；
  3. 前台窗口属于本进程（`GetForegroundWindow` + `GetWindowThreadProcessId` + `GetCurrentProcessId`）→ 放行，保证在 keymacro 设置页录制按键不误触发；
  4. keyup：查 `vk → rule_id` 表，命中则删表、投递 `Release(rule_id)`、返回 `LRESULT(1)`；
  5. keydown（含 Alt 组合的 `WM_SYSKEYDOWN`）：已在表中（按键连发）直接吞掉且不重复投递；否则归一化修饰键（`VK_LCONTROL/VK_RCONTROL→Ctrl` 等）+ `GetAsyncKeyState` 读当前修饰状态，**严格相等**匹配 + 主键 VK 匹配 + 状态条件满足 → 登记 `vk → rule_id`、投递 `Press(rule_id)`、吞键；任一不满足则放行。
- **worker 线程**：`recv` 事件后 `core.lock().handle_keyboard_event(...)`。绝不能在钩子回调里锁 `AppCore`（状态宏内部有 50ms 等待，低级钩子超时会被系统摘除）。
- **规则快照**：`Arc<RwLock<Arc<Vec<CompiledRule>>>>`，`CompiledRule { id, mods_bit, main_vk }`；`sync()` 整体替换，回调只做短读锁。
- `stop()` 时清空 `vk → rule_id` 表；调用 stop 时不得持有 core 锁（否则 worker 阻塞导致死锁）。

## 4. 配置持久化（`src/core/config.rs`）

- `profile_to_json` 增加顶层 `keyboardRules` 数组与 `globalSettings.keyboardRulesEnabled`。
- 每条规则字段：`id / enabled / ctrl / shift / alt / win / keyCode / mapping`，其中 `mapping` 直接复用现有 `mapping_to_json` / `parse_mapping`。
- 缺省兼容：字段缺失 → 空数组 / 默认开启；`CONFIG_VERSION` 保持 2，旧配置可直接加载。

## 5. 命令层（`src/commands.rs` + `src/main.rs`）

新增命令（返回/入参沿用现有 camelCase 约定）：
`get_keyboard_rules`、`add_keyboard_rule`、`delete_keyboard_rule`、`set_keyboard_rules_enabled`、`set_keyboard_rule_enabled`、`set_keyboard_rule_combo`、`set_keyboard_rule_action`、`toggle_keyboard_rule_sub`、`set_keyboard_rule_state_conditions`。

- `KeyboardRuleView`：`id / enabled / ctrl / shift / alt / win / keyCode / keyName / comboText / kind / desc / subs / stateConditions / stateLogic`（`#[serde(rename_all = "camelCase")]`）。
- 每次增删改后调用 `shared.sync_keyboard()` 刷新快照；`reset_config`、配置文件加载后同样 sync。

## 6. 前端

- 新页面 `frontend/keymacro.html` + `frontend/keymacro.js`：
  - 左栏：规则列表（启用圆点、组合键文本、动作描述、删除按钮）+「添加规则」；
  - 右栏：组合键录制（点击「录制」后用 `keydown` 捕获，修饰键单独记录、主键取第一个非修饰键；`event.key` 映射到 Android KeyCode 表）、动作类型 chips（keyboard / mouse / mousetoggle / wheelup / wheeldown / statemacro / interactionkey / releasemousetoggle / swapmousetoggle / finelook / toggleoverlayexpand）、目标选择、子命令 chips、状态条件 chips + 逻辑或/与、启用开关；
  - 100ms 轮询 `get_keyboard_rules` 刷新，风格完全复用 `.root/.panel/.panel-title/.chip/.btn/.select`，新增少量 `.rule-item` 样式；
  - 页面内提示：Win+L 等系统保留组合无法拦截。
- `frontend/index.html` 增加「键盘映射」入口按钮；`frontend/index.js` 增加 `openKeymacroWindow()`（复用 `WebviewWindow.getByLabel` 范式）与 prewarm。
- `capabilities/default.json` 的 `windows` 增加 `"keymacro-win"`。
- 窗口：`label = "keymacro-win"`、`url = keymacro.html`、约 900×560、可调整大小、与 edit-win 同样的 `backgroundColor/visible` 参数。

## 7. 版本与验证

- 版本号 `0.0.36 → 0.0.37`（`Cargo.toml`、`tauri.conf.json`）。
- `cargo build` 必须零错误。
- 实机验证清单：
  1. 配置 `Ctrl+Shift+1 → 状态宏(7)`，潜行状态下按下：光标居中并发出 7，游戏收不到该主键；
  2. 非潜行状态下按同一组合：动作不执行，且原键照常进游戏；
  3. 按住触发键：目标键持续按下；松开立即释放，无卡键；
  4. 未配置的按键完全不受影响（含打字、进出聊天框）；
  5. 在 keymacro 设置页录制按键不会触发规则；
  6. 停止映射 / 退出程序后钩子卸载，按键行为恢复正常、无卡键；
  7. 长按连发不会重复触发滚轮、鼠标锁存类动作。
- 不生成测试文件；验证完成后清理临时产物。
